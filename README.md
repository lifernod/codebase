> Умный поиск по кодовой базе. Понимаем ваш код и помогаем вам его понять!

## Проблема
Крупная IT-компания управляет десятками репозиториев. Новичок тратит 2-6 недель, чтобы разобраться где что реализовано. Опытные сотрудники ежедневно отвечают на повторяющиеся вопросы вместо того, чтобы решать новые задачи.

Стандартные инструменты поиска по коду (grep, полнотекстовый поиск) задачу решают плохо. Запрос "как здесь обрабатываются ошибки авторизации" не даст результата, потому что ни одно слово не совпадёт с именами функций в коде.

## Задача
Разработать прототип системы, которая понимает вопросы о коде на естественном языке и находит релевантные фрагменты, даже если слова вопроса не совпадают с именами переменных и функций.

## Используемые технологии
- Язык программирования - Python
- Библиотека парсинга файлов - Python ast
- Библиотека построения веб-интерфейса - Python streamlit
- REST API - Python FastAPI
- Векторная БД - ChromaDB

Для создание эмбеддингов использовалась библиотека [sentence_transformers](https://pypi.org/project/sentence-transformers). Модель `codefuse-ai/F2LLM-v2-0.6B` (локально)
1. Был обучен на основе кода
2. На основе тестов показал лучшие результаты

Для семантического поиска использовались библиотеки:
- Поиск BM25 - [bm25s](https://github.com/xhluca/bm25s)
- Векторный поиск - [ChromaDB](https://github.com/chroma-core/chroma)

Для генерации связанного ответа использовался сервис [OpenRouter](https://openrouter.ai/). Модель `google/gemini-2.5-flash-lite` (удалённо, через API)
1. Выдает максимальное количество токенов в секунду (оптимальное использование доступных ресурсов)

## Компоненты
---
### Компонент 1. Индексирующий скрипт
> Автономный Python-скрипт index.py. Принимает директорию с .py-файлами и выполняет три шага: парсинг файлов модулем ast на функции и классы, генерация эмбеддингов через sentence-transformers, сохранение в векторную БД.

Командой было принято решение **отказаться от автономного скрипта в пользу веб-интерфейса**. Вместо отдельного скрипта, который запускается локально, была сделана дополнительная страница на веб-сайте для загрузки туда кода. 
После того, как пользователь передает в специальное поле архив (.zip формата) с кодом, происходят слудеющие действия:
1. Архив передается на сервер и распаковывается во временную директорию (после окончания обработки директория очищается)
2. Индексация .py файлов:
	1. Рекурсивная выборка .py файлов из директории и поддиректорий (не .py файлы и файлы из .venv, pycache игнорируются)
	2. Чтение и парсинг файлов с помощью модуля ast
	3. Разбиение на чанки
3. Создание эмеддингов и сохранение векторов и метаданных в ChromaDB

### Стратегия чанкования
Чанкование происходит по функциям и методам классов, так как они представляют собой минимальные семантические единицы кода.
Для сохранения контекста окружения дополнительно формируются глобальные чанки .py файлов, содержащие импорты, конфигурационные вызовы, логику верхнего уровня и объявления глобальных переменных.
Отдельно выделяются чанки классов (без учета их методов), что позволяет эффективно индексировать структуры данных.
Для повышения точности семантического поиска было внедрено обогащение чанков метаданными (путь к файлу, принадлежность к классу, возвращаемое значение). Это придает дополнительный семантический вес векторам и позволяет LLM точно определять архитектурное расположение кода.

### Компонент 2. Векторная база ChromaDB
> Каждый чанк сохраняется с метаданными: путь к файла, тип (function/class), имя, номера строк, docstring. При поиске возвращаются топ-К ближайших соседей по вектору, а не по тексту

Выбор был сделан на ChromaDB, а не FAISS, по причине удобства использования: ChromaDB из коробки поставляет необходимые методы, которые пришлось бы писать вручную, используй мы FAISS, так как FAISS является лишь системой векторного поиска.

### Компонент 3. Веб интерфейс Streamlit
> Одна страница с полем ввода, кнопкой поиска и списком результатов. Каждый результат - карточка с путём к файлу, кодом с подстветкой синтаксиса и оценкой релевантности в процентах.

Помимо страницы с поиском, было принято решение добавить страницу с загрузкой архивов с кодом (подробнее было описано в Компоненте 1) и страницу с общими метриками ==(Среднее время ответа, Средняя точность ответов)==

### Компонент 4. LLM-ответы
> Полный RAG. Добавляется чат-режим: найденные фрагменты + вопрос передаются в LLM, который пишет связный ответ

Для создания связанного ответа была выбрана облочная модель `google/gemini-2.5-flash-lite` (OpenRouter). На вход модели передаются 5 самых релевантных чанков по мнению реранкинга, на основе которых строится связный ответ. Модель оценивает релевантность и насколько ответ подкреплен реальными чанками.
